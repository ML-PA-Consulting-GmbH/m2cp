L-IoT Documentation
  • 1. Glossary

1. Glossary

1.1. App

Any software package managed and distributed by the App Store Service. There are two types of Apps: 1) firmware updates for Real Time Devices and 2) snap packages for Edge Devices. Apps and assigned to Deployment Groups for delivery to devices.

1.2. App Store Registration

The process where a Device, after being flashed and connecting to the platform for the first time, communicates with the App Store Service. During registration, the service verifies the device, generates identifiers (like OS Serial Number for Edge Devices), performs security handshakes, and links the Device record to its pre-registered Asset record using the Device ID.

1.3. App Store Service

A Backend Service responsible for managing the entire software lifecycle for connected devices. It handles Apps (upload, verification, storage), defines device compatibility (Device Type, Device Model, Device Model Revision, Architecture), manages Deployment Groups, and orchestrates the secure delivery of software updates to eligible Devices. Currently, this service is not tenant-aware at the device level.

1.4. App Store UI

The section within the Ecosystem UI used to upload, manage, review, and assign Apps to Deployment Groups.

1.5. Architecture

Refers to the processor architecture of a Device, managed by the App Store Service. Those are ARM64 (for physical Edge Devices) and AMD64 (used for virtual devices in testing/development, which are not represented in the Asset Service). Architecture is a critical factor for software compatibility.

1.6. Asset

An individual instance of an Asset Model tracked within the Asset Service. It represents a specific physical entity. Each Device that runs on physical hardware is linked to a corresponding Asset which represents that specific Device Hardware in the Asset Service.

1.7. Asset Attestation Key

The public portion of a cryptographic key pair that is (usually, but not necessarily) generated within a Trusted Platform Module (TPM). It is stored as an asset property in the Asset Service before the device is added to the App Store Service. This key can be used to prove the identity of a piece of hardware. It is used when the OS running on that hardware wants to authorize with the App Store Service.

1.8. Asset Hierarchy

The parent-child structure used within the Asset Service to organize Assets. Allows modelling physical or logical relationships (e.g., an Edge Device asset being a child of a “System” asset). Each asset can have only one direct parent.

1.9. Asset Management UI

The section within the Ecosystem UI used to view, organize, and manage Assets, Asset Types, Asset Models, and Asset Hierarchies.

1.10. Asset Model

A specific template or model within an Asset Type, defined in the Asset Service (e.g., the “Gateway_123” model under the “Edge Device” Asset Type). For IoT devices, an Asset Model is automatically created in the Asset Service when a corresponding Device Model Revision is created in the App Store Service, and it includes the Device Model Revision ID as a link.

1.11. Asset Name

The identifier used for an Asset within the Asset Service and displayed in the Asset/Device Overview sections of the UI. For assets representing Devices synced from the App Store Service, this name is automatically generated in the format: [Asset Model Name]-[OS Serial Number].

NOTE: The Device Name and the Asset Name are independent. One is the name of a software instance, and the latter is the representation of the device hardware. Asset Admin can potentially rename assets in the Asset Service.

1.12. Asset Service

A Backend Service responsible for managing the inventory of physical and logical entities (Assets). It tracks Asset Types, Asset Models, individual Assets, their status, and their relationships (Asset Hierarchy). It provides the data for the Asset Overview and Device Overview sections in the UI. This service is tenant aware.

1.13. Asset Type

A user-defined category used in the Asset Service to classify Assets (e.g., “Edge Device”, “Wagon”, “Sensor Array”, “Room”).

1.14. Asset Type Category

A system-defined classification (enum) assigned to each Asset Type in the Asset Service. Possible values are Edge device, Real time device, and Asset. This category is used by the UI to filter which items appear in the “Asset Overview” (shows Asset category) versus the “Device Overview” (shows Edge device and Real time device categories).

1.15. Backend Services

The collection of server-side applications that provide the core functionality of the platform, supporting the UI. It includes the App Store Service, Asset Service and User Service.

1.16. Deployment Group

A named collection of Devices within the App Store Service, used to manage software distribution. Apps are assigned to Deployment Groups, and all devices within that group are targeted to receive those specific Apps (or updates). Devices in a deployment group must be of the exact same Device Model.

1.17. Device

The representation of a specific piece of hardware within the App Store Service, primarily defined by its software compatibility characteristics (Device Type, Device Model, Device Model Revision, Architecture). The App Store Service manages software deployments to these Devices.

1.18. Device ID

A unique internal identifier (Universally Unique Identifier) generated by the platform’s database when a device’s corresponding Asset is first created/registered in the Asset Service. It serves as the primary technical link (primary key) connecting the Asset record in the Asset Service with the Device record in the App Store Service. This ID is generally not visible or used directly by users in the UI.

1.19. Device Hardware

Hardware of an Edge Device or Real Time Device.

1.20. Device Management

One of the platform’s key capabilities, encompassing the commissioning, organization (e.g., via Asset Hierarchy or Deployment Groups), and monitoring of Devices and other Assets. Primarily managed through the Asset Service (for inventory/status) and App Store Service (for software grouping/deployment).

1.21. Device Model

Every Device has a Device Model which describes its compatibility profile (e.g. processor architecture).

1.22. Device Model Name

The name of the Device Model. This is a user-defined string that is used to identify the Device Model in the App Store Service.

1.23. Device Model Revision

Existing Device Models can’t be modified. When a new variant is required, it is created under the same name but with a higher Device Model Revision (i.e. a higher version number).

1.24. Device Name

An optional, user-defined name that can be assigned to a Device within the App Store Service.

NOTE: The Device Name and the Asset Name are independent. One is the name of a software instance, and the latter is the representation of the Device Hardware.

1.25. Device Type

A logical classification used in the App Store Service to categorize Devices based on their fundamental role or capability (e.g., “Edge Device”, “Real Time Device”).

1.26. Ecosystem UI

A browser-based frontend to review and manage the components inside L-IoT. It contains the App Store UI and the Asset Management UI as subsections.

1.27. Edge Device

A type of Device, more powerful than a Real Time Device, running Edge OS and multiple applications (Apps delivered as snaps), and often acting as a gateway for other devices.

(Replaces the overloaded legacy term “the M2CP” when referring to the device itself).

1.28. Edge Device SDK

An installable system component packaged as a Debian package that bundles modules and their dependencies to simplify the integration of messaging into Apps. The ML!PA Edge Device SDK is available in both Go and Python, but we recommend using the Go version.

1.29. Edge OS

A family of Linux based OS maintained by ML!PA running on Edge Devices.

1.30. Firmware Package

A type of App distributed to Real Time Devices, containing the complete software image for the device’s operation.

1.31. Hardware Model

A specific hardware design or configuration, referring to a series of devices that share the same components, architecture, and wiring.

1.32. Hardware Model Name

The name of the Hardware Model. This is a user-defined string that is used to identify the Hardware Model. Legacy term: ‘board’

1.33. Hardware Vendor

The name of the vendor of the hardware. Used to uniquely identify a specific piece of hardware.

1.34. Hardware Model Revision

LEGACY: If a modification is made to an existing hardware design, the Hardware Model Revision can be incremented to express this.

1.35. Hardware Serial Number

The unique identifier of the Device Hardware of an Edge Device or a Real Time Device.

1.36. MCU ID

The MCU ID is required, if multiple MCUs are contained in a single piece of hardware. In that case, multiple Real Time Devices share the same Hardware Serial Number and require the MCU ID for unique identification, e.g. for the firmware update mechanism. The MCU ID value is a string.

1.37. M2CP

Legacy name of L-IoT. The term “the M2CP” used to refer to an Edge Device. Many Apps and tools still contain an m2cp- prefix due to this heritage

1.38. m2cp-coap

Edge Device application acting as a gateway towards Real Time Devices

1.39. m2cp-gateway

Edge Device application acting as a gateway towrads the Cloud Backend

1.40. m2cp-message-hub

Local message broker on Edge Device which allows Edge Device apps to communicate with each other.

1.41. L-IoT

L-IoT (formerly ML!PA Ecosystem) is an IoT management platform designed for clients who need to manage their IoT devices.

Software development and distribution is supported by the use of the SDKs (e.g. Radio Network, Bluetooth, Security Features) and Toolchains (e.g. Build Tool) needed to quickly build reliable Applications for Edge Devices.

Additionally, the platform enables users to monitor Devices (data points collection and logs), manage Assets and users and control devices remotely (RPC).

1.42. OS Serial Number

A unique identifier for a Device in the App Store. The value is a UUID string.

For Edge Devices this ID is deterministically derived from the Asset Attestation Key, the Device Model Name, and the Device Model Revision. Thus the Edge Device will always receive the same OS Serial Number even when reinstalling the same OS.

If there is no TPM available to generate the Asset Attestation Key, then a fallback mechanism is implemented. If the block devices provide deterministic identifiers, then these will be included in the calculation, else the MAC addresses of network interfaces will be used. If all the efforts fail, then an a random UUID is used.

For Real Time Devices the OS Serial Number is deterministically calculated from the hardware properties. The calculation is described in detail in the Firmware Updates Data Formats section.

1.43. Real Time Device

A type of Device, simpler than an Edge Device, running dedicated firmware and not a full operating system. Often sensors or actuators connected to an Edge Device. Represented as both a Device (App Store Service) and an Asset (Asset Service, with category Real time device). Does not have an OS Serial Number or Asset Attestation Key. It is identified by a Hardware Serial Number and the MCU ID, if multiple RTDs share the same Hardware Serial Number.

1.44. Real Time Device SDK

A library in C that can be used to develop firmware.

1.45. Snapd

An Edge OS core app originally built by Canonical that is used to install, run and update all applications on Edge Devices. (Snapd Github Link)

1.46. Snap Package

A type of containerized App format typically used for distributing applications to Edge Devices running a compatible Linux OS.

1.47. Tenant

An isolated environment within the platform, typically representing a single customer or organizational unit. The Asset Service is tenant-aware (users see only their tenant’s assets), while in App Store Service users will see devices across tenants.

1.48. User Service

A Backend Service responsible for managing user authentication, authorization, and user account management within the platform. It handles user roles, permissions, and access control across the ecosystem.

1.49. Virtual Device

A Docker container for AMD64 whose instances behave very much like a real Edge Devices – a very useful tool for App developers. Virtual Devices are managed by the App Store Service but are not represented as Assets in the Asset Service and are therefore not visible in the standard Asset/Device Overview UI sections.
